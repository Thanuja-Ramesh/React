React Fundamentals & Architecture

A comprehensive engineering guide covering core paradigms, declarative UI, component modularity, JSX compilation, Virtual DOM, and the reconciliation cycle.

1. What is React?

React is an open-source JavaScript library developed by Facebook (Meta) and open-sourced in 2013. It is engineered specifically for building modular, interactive, and performant user interfaces, especially for Single Page Applications (SPAs).

Key Paradigm Shift: Traditional vanilla JavaScript uses an imperative approach where developers manually target DOM nodes (e.g. document.getElementById) and modify them. React introduces a declarative approach where you describe the target UI based on the current state, and React handles all underlying DOM mutations efficiently.

2. Is React a Library or a Framework?

React is strictly a library, not a framework. It is unopinionated and focuses exclusively on the view layer (V in MVC).

Feature React (Library) Framework (e.g., Angular)
Scope View Layer Only Full End-to-End Suite
Routing & State Ecosystem choices (React Router, Redux, Zustand) Built-in strictly
Control Inversion Developer calls the library Framework controls application flow
Flexibility Extremely high modularity Opinionated architecture

3. What is a Component?

A component is a self-contained, reusable piece of user interface. In modern React, components are pure or semi-pure JavaScript functions that accept inputs (called props) and return JSX describing what should appear on the screen.

// Example of a Reusable Functional Component function WelcomeBanner({ name }) { return ( <div className="banner"> <h1>Welcome back, {name}!</h1> <p>Explore your dashboard below.</p> </div> ); } export default WelcomeBanner;

4. Why are Components Important?

Consider constructing a real-world e-commerce platform.

Without component architecture: You end up with a single massive file containing thousands of lines combining Header, Banner, Products list, Cart sidebar, Checkout modal, and Footer. Fixing one minor bug risks breaking unrelated elements.

With React component architecture: Each feature is isolated into its own file:

  • Reusability: Create a <ProductCard /> or <Button /> once, render it hundreds of times across different routes.
  • Maintainability & Readability: Small, isolated components make codebases intuitive to navigate.
  • Separation of Concerns: Each component manages its own styling, DOM representation, and state.
  • Testability: Independent units can be easily tested with unit and integration tests.

5. What is JSX (JavaScript XML)?

JSX is a syntax extension for JavaScript that looks similar to HTML. It enables developers to author visual component structure directly alongside application logic.

const App = () => { return ( <div className="app-container"> <h2>Hello React 19</h2> <p>Declarative UI powered by Vite.</p> </div> ); };

Browsers cannot natively execute JSX. Modern build tools (such as Vite with esbuild/rolldown or Babel) compile JSX into standard JavaScript (React.createElement or the modern JSX runtime).

6. Real DOM vs. Virtual DOM

Real DOM: The tree representation of HTML elements created by the browser. Mutating the real DOM directly is computationally expensive because it causes layout reflows and repaints.

Virtual DOM (VDOM): A lightweight JavaScript object tree representation of the Real DOM kept in memory. When changes occur, React updates the Virtual DOM instantaneously in memory without triggering costly browser repaints.

7. What is Reconciliation & Diffing?

Reconciliation is the algorithm React uses to synchronize the Virtual DOM with the Real DOM.

  • When state or props change, React generates a new Virtual DOM tree.
  • React runs a fast diffing algorithm (O(n) heuristic) comparing the new tree with the previous snapshot.
  • It isolates only the exact subtrees or nodes that actually changed.
  • React batches and commits only those minimal modifications to the real browser DOM.
